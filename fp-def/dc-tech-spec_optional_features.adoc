O NetApp oferece suporte a vários componentes opcionais para aprimorar ainda mais as arquiteturas de data center do FlexPod. Os componentes opcionais estão descritos nas subseções a seguir.


NOTE: A inicialização SAN é opcional, mas altamente recomendada, pois permite a movimentação do perfil do servidor durante upgrades ou substituições de hardware.



[[iscsi-boot-option]]
== Opção de inicialização iSCSI

Os requisitos mínimos para a opção de inicialização iSCSI incluem:

* Uma licença/funcionalidade iSCSI ativada no controlador de armazenamento NetApp
* Um adaptador Ethernet 10Gbps de duas portas em cada nó no par de HA do controlador de storage NetApp
* Um adaptador no servidor Cisco UCS que é capaz de inicializar iSCSI

[[fc-boot-with-cisco-mds]]
== Inicialização FC com Cisco MDS

Para proporcionar maior escalabilidade usando uma rede SAN dedicada, o FlexPod oferece suporte a FC por meio dos switches Cisco MDS. A opção de boot SAN FC por meio do Cisco MDS possui os seguintes requisitos de modelo de licenciamento e hardware:

* Um mínimo de duas portas FC por controlador de storage NetApp; uma porta para cada malha SAN
* Uma licença FC em cada controlador de armazenamento NetApp.
* Um adaptador no servidor Cisco UCS que é capaz de inicialização FC.


A figura a seguir mostra um exemplo do FlexPod Datacenter com o X-Series Modular System e servidores de rack da C-Series para configuração SAN baseada em FC com switches MDS.

image:dc-tech-spec_image16.png["FlexPod Datacenter para conectividade SAN baseada em FC"]

Para obter mais informações sobre esta configuração, consulte link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter com Cisco UCS M7 IMM, VMware vSphere 8.0 e NetApp ONTAP 9.12 Guia de Projeto"^].

[[end-to-end-fc-nvme]]
== FC-NVMe completo

Uma solução FC-NVMe completamente de ponta a ponta amplia perfeitamente a infraestrutura SAN existente do seu cliente para aplicações em tempo real, oferecendo simultaneamente IOPS e throughput aprimorados com latência reduzida. Um transporte SAN FC de 32G existente pode ser usado para transportar simultaneamente cargas de trabalho NVMe e SCSI.

Para obter mais informações sobre esta configuração, consulte link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter com Cisco UCS M7 IMM, VMware vSphere 8.0 e NetApp ONTAP 9.12 Guia de Projeto"^].



[[cisco-ucs-x-series-direct-and-direct-attached-aff-asa-fas-for-fc-and-ip-based-san]]
== Cisco UCS Série X direto e AFF/ ASA/ FAS conectados diretamente para SAN baseadas em FC e IP

NetApp storage controllers podem ser conectados diretamente aos interconectores de malha do Cisco UCS sem a necessidade de um switch SAN upstream. FlexPod oferece suporte tanto à inicialização FC quanto iSCSI com o UCS X-Series Direct.

Os requisitos de licenciamento e hardware são os seguintes:

* É necessária uma licença de protocolo no controlador de storage NetApp.
* É necessário um adaptador Cisco UCS (iniciador) no servidor. Para obter uma lista de adaptadores Cisco UCS compatíveis, consulte o NetApp https://imt.netapp.com["IMT"^].
* É necessário um adaptador de destino no controlador de armazenamento NetApp.

image:dc-tech-spec_image13.png["Topologia Direct e direct-attached ASA da UCS X-Series para SAN baseada em IP"]

*Notas:*

* O Cisco UCS está configurado no modo de comutação Ethernet.
* As interconexões de portas iSCSI do destino para a malha são configuradas como portas de storage Ethernet para dados iSCSI.


A figura a seguir mostra uma topologia UCS X-Series Direct e ASA conectada diretamente para SAN baseada em IP e baseada em FC.

image:dc-tech-spec_image14.png["Topologia direta e de conexão direta ASA da UCS X-Series para SAN baseada em IP e FC"]

*Notas:*

* O Cisco UCS é configurado no modo de comutação FC.

[[metrocluster]]
== MetroCluster

A solução FlexPod MetroCluster IP com VXLAN Multi-Site fabric consiste em dois FlexPods, localizados em dois sites separados por certa distância, mas conectados e emparelhados para fornecer uma solução de data center altamente disponível, altamente flexível e altamente confiável, capaz de garantir a continuidade dos negócios mesmo em caso de falha do local. A distância máxima suportada entre os sites é de aproximadamente 435 milhas (700 km).

Na solução IP do FlexPod MetroCluster, a solução Cisco VXLAN Multi-Site permite que você interconecte e gerencie centralmente fabrics VXLAN implantadas em data centers separados e geograficamente dispersos. O NetApp MetroCluster IP oferece uma solução de replicação síncrona entre dois clusters de armazenamento NetApp, proporcionando alta disponibilidade de storage e recuperação de desastres em um campus ou área metropolitana. A solução permite que você projete uma nuvem privada baseada em VMware vSphere em uma infraestrutura integrada e distribuída, oferecendo uma solução unificada que permite que vários sites se comportem de maneira muito semelhante a um único site, protegendo os serviços de dados contra diversos cenários de falha em um único ponto, incluindo a falha do local.

[[snapmirror-active-sync-solution-for-flexpod-metrocluster-ip-solution]]
=== SnapMirror solução active sync para FlexPod MetroCluster solução IP

Utilizando a tecnologia Snapshot da NetApp no software NetApp ONTAP, os serviços de dados SAN de missão crítica podem ser restaurados rapidamente com dados de backups baseados em Snapshot.

* Os dois clusters ONTAP implantados em dois locais diferentes estão interligados e configurados com SnapMirror active sync para replicação síncrona de dados e recuperação de desastres.
* O ONTAP Mediator é implantado em um terceiro domínio de falha, conforme mostrado na figura abaixo. Juntamente com os clusters, o ONTAP Mediator completa o quorum para a solução SnapMirror active sync.
* O mediador do ONTAP recebe informações de integridade dos clusters e nós do ONTAP interligados e orquestra a comunicação entre eles para determinar seu status. Os dados de integridade ajudam os clusters a distinguir entre vários tipos de falhas e decidir se devem realizar um failover automatizado.


image:dc-tech-spec_image18.png["Componentes da solução SnapMirror active sync para a solução IP do FlexPod MetroCluster"]
